Social Inbox Frontend Guide

Backend gaps to resolve

Raise these with the backend team first. Gaps 1 to 3 change what can ship.

1

The inbox cannot read messages

The reference has send/text but nothing that lists conversations or messages. Incoming messages go to Meta webhooks on the server, and no route or live stream passes them on to the browser. Recipient IDs also come from incoming messages, so an agent has no way to get one.

Ask: add the read endpoints and a live stream. A proposed contract is below.

2

5 requests per minute is too low for an inbox

The limit is shared across all endpoints, per IP. Opening the dashboard costs 4 requests (/me and three channel lists), which leaves 1 for that minute. Everyone in one office usually shares an IP, so colleagues use up each other's allowance.

Ask: limit per user, with separate budgets for login and for normal use, and send a Retry-After header on 429.

3

There is no way to list or manage chatbots

Connect endpoints accept a chatbot_id, but the reference has no route to list chatbots, create them or find a widget's access key. A chatbot picker has nothing to show.

Ask: add GET /api/chatbots at minimum, and say where widget keys come from.

4

Changing a channel's chatbot means re-entering credentials

The only documented way is to connect again, with an access token or a fresh OAuth flow. The reference also doesn't say how to clear a chatbot back to null.

Ask: add PATCH /api/channels/{platform}/{id} taking { "chatbot_id": "…" | null }.

5

The bot and a human agent can both reply

Auto-replies are set per channel. Nothing lets an agent take over a single conversation, so customers could get two answers.

Ask: add a per-conversation handoff setting.

6

Widget requests cross origins

The widget runs on other people's sites, so the API must allow those origins, the custom headers, and expose x-session-id through Access-Control-Expose-Headers. Without that, the header reads as null and every message starts a new conversation. The question also travels in the URL, so it can end up in access logs and is limited in length.

Ask: confirm the CORS setup, and accept the question in a JSON body.

7

Tokens have to be readable by JavaScript

Because tokens are returned in JSON, the app has to store them where any cross-site scripting bug could read them. This guide uses localStorage so tabs can share them.

Ask: consider an HttpOnly cookie for the refresh token. Until then, keep a strict Content Security Policy and never render message content as HTML.

8

OAuth redirects always go to production

The redirect pages are fixed to sproject-frontend.vercel.app, so a login started on localhost returns to the deployed site. The state also belongs to the API that issued it.

Ask: make the redirect URI configurable per environment and add the local URL to the Meta app settings.

9

The product designs need more data

The Integrations page has an on/off switch for the chat widget, and the API has no route for it. The inbox shows AI labels, tags and sorting, which the proposed contract now includes. The sample messages also thank people for comments, but the API only documents direct messages.

Ask: add a widget on/off route, and confirm whether comment replies are in scope and whether tags are set by AI or by agents.

Use TanStack Query for data you read again, such as channel lists. Use use() only for a promise you keep stable outside the component. A promise created during render makes the component suspend forever.

Keep StrictMode on, and be careful with single-use values. In development it runs effects twice, so a callback in useEffect would spend the OAuth state on the first call and show an error from the second.

React resets uncontrolled forms after an action finishes. Where a failed send must keep the text, hold it in state, as the composer does.

Sign-in and tokens

TokenLifetimeUse
access_token15 minutes (expires_in is in seconds)Authorization: Bearer … on protected requests
refresh_token7 days, single useGets a new pair from /refresh
  1. A protected request returns 401.
  2. Call /refresh once with the stored refresh token, and save both new tokens.
  3. Retry the original request.
  4. If /refresh also returns 401, clear the tokens and go to login.

Each refresh token works once, so two tabs refreshing together would log the user out. The client below prevents that with the Web Locks API. Tests confirmed that parallel 401s produce one refresh, that a token already refreshed by another tab is reused, and that a login 401 never triggers a refresh. Those tests used a simulated lock, not two real browser tabs.

src/lib/session.ts

import { useSyncExternalStore } from "react";
import type { TokenPair } from "./types";

const KEY = "auth";
const listeners = new Set<() => void>();

function emit() {
  listeners.forEach((listener) => listener());
}

export function readTokens(): TokenPair | null {
  const raw = localStorage.getItem(KEY);
  return raw ? (JSON.parse(raw) as TokenPair) : null;
}

export function saveTokens(tokens: TokenPair | null) {
  if (tokens) localStorage.setItem(KEY, JSON.stringify(tokens));
  else localStorage.removeItem(KEY);
  emit();
}

// `storage` fires in the other tabs, so logging out in one logs out all of them.
function subscribe(listener: () => void) {
  listeners.add(listener);
  window.addEventListener("storage", listener);
  return () => {
    listeners.delete(listener);
    window.removeEventListener("storage", listener);
  };
}

export function useIsSignedIn() {
  return useSyncExternalStore(subscribe, () => localStorage.getItem(KEY) !== null);
}

src/lib/api.ts

import { readTokens, saveTokens } from "./session";
import type { TokenPair } from "./types";

const BASE_URL = import.meta.env.VITE_API_BASE_URL;

interface ValidationIssue {
  loc: (string | number)[];
  msg: string;
  type: string;
}

export class ApiError extends Error {
  constructor(
    readonly status: number,
    readonly detail: string,
    readonly issues: ValidationIssue[] = [],
  ) {
    super(detail);
  }

  /** Maps a 422 to { email: "value is not a valid email address" }. */
  get fieldErrors(): Record<string, string> {
    return Object.fromEntries(
      this.issues.map((issue) => [String(issue.loc.at(-1)), issue.msg]),
    );
  }
}

async function toApiError(response: Response) {
  const body = await response.json().catch(() => null);
  const detail: unknown = body?.detail;
  if (Array.isArray(detail)) {
    return new ApiError(response.status, "Check the highlighted fields.", detail);
  }
  return new ApiError(
    response.status,
    typeof detail === "string" ? detail : `Request failed (${response.status})`,
  );
}

let refreshing: Promise<string> | null = null;

/**
 * Refresh tokens work once, so one refresh runs at a time across all tabs:
 * `refreshing` joins callers in this tab, the Web Lock queues the other tabs.
 */
function refreshAccessToken(rejectedToken: string) {
  refreshing ??= navigator.locks
    .request("auth-refresh", async () => {
      const stored = readTokens();
      if (!stored) throw new ApiError(401, "Signed out");

      // Another tab refreshed while this one waited for the lock.
      if (stored.access_token !== rejectedToken) return stored.access_token;

      const response = await fetch(`${BASE_URL}/api/auth/user/refresh`, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ refresh_token: stored.refresh_token }),
      });
      if (response.status === 401) saveTokens(null);
      if (!response.ok) throw await toApiError(response);

      const next = (await response.json()) as TokenPair;
      saveTokens(next);
      return next.access_token;
    })
    .finally(() => {
      refreshing = null;
    });
  return refreshing;
}

interface ApiOptions {
  method?: "GET" | "POST" | "DELETE";
  body?: unknown;
  auth?: boolean; // false for login, register and the like
  signal?: AbortSignal;
}

export async function api<T>(path: string, options: ApiOptions = {}): Promise<T> {
  const { method = "GET", body, auth = true, signal } = options;

  const send = (token?: string) =>
    fetch(`${BASE_URL}${path}`, {
      method,
      signal,
      headers: {
        ...(body !== undefined && { "Content-Type": "application/json" }),
        ...(token && { Authorization: `Bearer ${token}` }),
      },
      body: body === undefined ? undefined : JSON.stringify(body),
    });

  const token = auth ? readTokens()?.access_token : undefined;
  let response = await send(token);

  if (response.status === 401 && token) {
    response = await send(await refreshAccessToken(token));
  }
  if (!response.ok) throw await toApiError(response);
  return (response.status === 204 ? undefined : await response.json()) as T;
}

Login form

Register does not log the user in, so call login after it. 401 uses the same message whether or not the email exists, and 403 means the account is disabled.

src/features/auth/LoginForm.tsx

import { useActionState } from "react";
import { useFormStatus } from "react-dom";
import { useNavigate } from "react-router";
import { api, ApiError } from "../../lib/api";
import { saveTokens } from "../../lib/session";
import type { TokenPair } from "../../lib/types";

interface LoginState {
  error?: string;
  fields?: Record<string, string>;
}

function SubmitButton() {
  const { pending } = useFormStatus();
  return <button disabled={pending}>{pending ? "Signing in…" : "Sign in"}</button>;
}

export function LoginForm() {
  const navigate = useNavigate();

  const [state, formAction] = useActionState(
    async (_previous: LoginState, form: FormData): Promise<LoginState> => {
      try {
        const tokens = await api<TokenPair>("/api/auth/user/login", {
          method: "POST",
          auth: false,
          body: { email: form.get("email"), password: form.get("password") },
        });
        saveTokens(tokens);
        await navigate("/inbox");
        return {};
      } catch (error) {
        if (error instanceof ApiError) {
          return { error: error.detail, fields: error.fieldErrors };
        }
        return { error: "Could not reach the server. Try again." };
      }
    },
    {},
  );

  return (
    <form action={formAction}>
      <title>Sign in</title>
      <label htmlFor="email">Email</label>
      <input id="email" name="email" type="email" autoComplete="username" required />
      {state.fields?.email && <p role="alert">{state.fields.email}</p>}

      <label htmlFor="password">Password</label>
      <input id="password" name="password" type="password" autoComplete="current-password" required />
      {state.fields?.password && <p role="alert">{state.fields.password}</p>}

      {state.error && <p role="alert">{state.error}</p>}
      <SubmitButton />
    </form>
  );
}

Working within the rate limit

All endpoints share 5 requests per minute per IP. Going over returns 429 { "detail": "Rate limit exceeded" }. Until gap 2 is fixed:

  • Load the three channel lists once for the Integrations cards, then reuse the cache. Don't fetch them again when someone clicks Manage.
  • Never poll. Run /status and /details only when someone opens that channel.
  • Don't retry 429 automatically. Show "Too many requests. Wait a minute and try again."
  • Reuse the data returned by connect, token and reconnect instead of fetching the list again where you can.

src/lib/queryClient.ts

import { QueryClient } from "@tanstack/react-query";
import { ApiError } from "./api";

// 5 requests per minute per IP: no background refetching, no retry on 4xx.
export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60_000,
      refetchOnWindowFocus: false,
      refetchOnReconnect: false,
      retry: (count, error) =>
        count < 1 && !(error instanceof ApiError && error.status < 500),
    },
  },
});

Channels

A channel is one connected Facebook page, Instagram account or WhatsApp number. Always use external_id in URLs, not id. Access tokens are never returned, so treat any token input as write-only: use type="password" and autoComplete="off".

src/features/channels/channelApi.ts

import { api } from "../../lib/api";
import type { Channel, ChannelStatus, Platform, SendTextResponse } from "../../lib/types";

const base = (platform: Platform) => `/api/channels/${platform}`;
const id = encodeURIComponent;

export const channelApi = {
  list: (platform: Platform) => api<Channel[]>(base(platform)),

  // Live call to Meta. Run it when a channel panel opens, never in a loop.
  status: (channel: Channel) =>
    api<ChannelStatus>(`${base(channel.platform)}/${id(channel.external_id)}/status`),

  reconnect: (channel: Channel) =>
    api<Channel>(`${base(channel.platform)}/${id(channel.external_id)}/reconnect`, {
      method: "POST",
    }),

  disconnect: (channel: Channel) =>
    api<Channel>(`${base(channel.platform)}/${id(channel.external_id)}`, {
      method: "DELETE",
    }),

  remove: (channel: Channel) =>
    api<void>(`${base(channel.platform)}/${id(channel.external_id)}/remove`, {
      method: "DELETE",
    }),
};

// Each platform names its send fields differently and truncates at its own length.
export const MAX_TEXT: Record<Platform, number> = {
  facebook: 2000,
  instagram: 1000,
  whatsapp: 4096,
};

export function sendText(channel: Channel, recipient: string, text: string) {
  const bodies: Record<Platform, object> = {
    facebook: { page_id: channel.external_id, recipient_id: recipient, text },
    instagram: { instagram_id: channel.external_id, recipient_id: recipient, text },
    whatsapp: { phone_number_id: channel.external_id, to: recipient, text },
  };
  return api<SendTextResponse>(`${base(channel.platform)}/send/text`, {
    method: "POST",
    body: bodies[channel.platform],
  });
}

src/features/channels/useChannels.ts

import { useMutation, useQuery, useQueryClient } from "@tanstack/react-query";
import { channelApi } from "./channelApi";
import type { Channel, Platform } from "../../lib/types";

export function useChannels(platform: Platform) {
  return useQuery({
    queryKey: ["channels", platform],
    queryFn: () => channelApi.list(platform),
  });
}

// Pass enabled={panelIsOpen} so the live check only runs when someone looks.
export function useChannelStatus(channel: Channel, enabled: boolean) {
  return useQuery({
    queryKey: ["channel-status", channel.platform, channel.external_id],
    queryFn: () => channelApi.status(channel),
    enabled,
    staleTime: 60_000,
  });
}

export function useDisconnect() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: channelApi.disconnect,
    onSuccess: (_updated, channel) =>
      queryClient.invalidateQueries({ queryKey: ["channels", channel.platform] }),
  });

  1. GET /oauth/url returns { url, state }.
  2. Send the browser to url and the user approves.
  3. Facebook returns to /social-media-integration/facebook?code=…&state=….
  4. POST /oauth/callback with { code, state } returns the user's pages.
  5. The user ticks pages and optionally picks a chatbot.
  6. POST /pages/connect returns the connected channels.

state lasts 10 minutes, works once, and only for the user who requested it. After 400 "Invalid or expired OAuth state", restart from step 1. The page list is kept on the server for 10 minutes, so connect within that time.

src/features/channels/FacebookCallback.tsx

import { Suspense, use } from "react";
import { ErrorBoundary } from "react-error-boundary";
import { Link, useSearchParams } from "react-router";
import { api, ApiError } from "../../lib/api";
import type { FacebookPage } from "../../lib/types";

// `state` works once and StrictMode renders twice, so the request is keyed
// outside React. Both renders then read the same promise.
const exchanges = new Map<string, Promise<FacebookPage[]>>();

function exchangeCode(code: string, state: string) {
  let exchange = exchanges.get(state);
  if (!exchange) {
    exchange = api<FacebookPage[]>("/api/channels/facebook/oauth/callback", {
      method: "POST",
      body: { code, state },
    });
    exchanges.set(state, exchange);
  }
  return exchange;
}

function PagePicker({ code, state }: { code: string; state: string }) {
  const pages = use(exchangeCode(code, state));

  async function connect(form: FormData) {
    await api("/api/channels/facebook/pages/connect", {
      method: "POST",
      body: { page_ids: form.getAll("page_id") },
    });
    window.location.assign("/channels");
  }

  return (
    <form action={connect}>
      {pages.map((page) => (
        <label key={page.id}>
          <input type="checkbox" name="page_id" value={page.id} />
          {page.name} {page.connected && "(already connected)"}
        </label>
      ))}
      <button>Connect selected pages</button>
    </form>
  );
}

export function FacebookCallback() {
  const [params] = useSearchParams();
  const code = params.get("code");
  const state = params.get("state");

  if (!code || !state) return <p>Facebook did not grant access.</p>;

  return (
    <ErrorBoundary
      fallbackRender={({ error }) => (
        <p role="alert">
          {error instanceof ApiError ? error.detail : "Something went wrong."}{" "}
          <Link to="/channels">Start again</Link>
        </p>
      )}
    >
      <Suspense fallback={<p>Loading your pages…</p>}>
        <PagePicker code={code} state={state} />
      </Suspense>
    </ErrorBoundary>
  );
}

src/features/inbox/Composer.tsx

import { useOptimistic, useState } from "react";
import { MAX_TEXT, sendText } from "../channels/channelApi";
import { ApiError } from "../../lib/api";
import type { Channel } from "../../lib/types";

interface Bubble {
  key: string;
  text: string;
  pending?: boolean;
}

interface ComposerProps {
  channel: Channel;
  recipient: string; // PSID, Instagram-scoped ID, or WhatsApp number
  messages: Bubble[];
  onSent: (message: Bubble) => void;
}

export function Composer({ channel, recipient, messages, onSent }: ComposerProps) {
  const [draft, setDraft] = useState("");
  const [error, setError] = useState<string | null>(null);
  const [optimistic, addOptimistic] = useOptimistic(
    messages,
    (current, text: string): Bubble[] => [
      ...current,
      { key: `pending-${current.length}`, text, pending: true },
    ],
  );

  async function send() {
    const text = draft.trim();
    if (!text) return;

    setError(null);
    addOptimistic(text);
    setDraft("");
    try {
      const { message_id } = await sendText(channel, recipient, text);
      onSent({ key: message_id, text });
    } catch (caught) {
      setDraft(text); // give the failed message back to the agent
      setError(caught instanceof ApiError ? caught.detail : "Message not sent. Try again.");
    }
  }

  return (
    <>
      <ol aria-live="polite">
        {optimistic.map((message) => (
          <li key={message.key} aria-busy={message.pending}>{message.text}</li>
        ))}
      </ol>
      {error && <p role="alert">{error}</p>}
      <form action={send}>
        <label htmlFor="reply">Reply</label>
        <textarea
          id="reply"
          value={draft}
          onChange={(event) => setDraft(event.target.value)}
          required
          maxLength={MAX_TEXT[channel.platform]}
          disabled={!channel.is_active}
        />
        <button disabled={!channel.is_active}>Send</button>
      </form>
    </>
  );
}

Chatbot

The chatbot appears in two separate places.

Build the widget separately

Give the widget its own Vite entry point and bundle. It should not include the dashboard's router, query cache or session code, and a host site shouldn't have to load them. Render it in a Shadow DOM so the host page's CSS can't affect it.

  • Treat the key as public. The widget's X-API-Key is visible to anyone viewing the page source. Confirm with the backend team that it only grants widget access.
  • Don't show context. It holds the retrieved source text and is only useful for debugging.
  • Render answers as plain text. If you add Markdown later, use a sanitizing renderer.
  • Plan for the shared limit. Loading config uses one request, leaving four questions in the first minute. Show a friendly message on 429.
  • Apply the config. GET /chat/config supplies the greeting, alignment, colors and FAQ list. Sending an FAQ works the same as typing it.

History expires after 1 hour of inactivity. Save x-session-id and send it back as session-id on later messages. Omit the header on the first message.

src/features/widget/chatApi.ts

import type { ChatResponse } from "../../lib/types";

export interface WidgetKeys {
  baseUrl: string;
  apiKey: string;
  chatbotId: string;
}

const SESSION_KEY = "chat-session-id";

export async function askChatbot({ baseUrl, apiKey, chatbotId }: WidgetKeys, query: string) {
  const sessionId = sessionStorage.getItem(SESSION_KEY);

  const response = await fetch(
    `${baseUrl}/api/public/chat?query=${encodeURIComponent(query)}`,
    {
      method: "POST",
      headers: {
        "X-API-Key": apiKey,
        "chatbot-id": chatbotId,
        ...(sessionId && { "session-id": sessionId }),
      },
    },
  );
  if (!response.ok) throw new Error(`Chat failed (${response.status})`);

  // The browser only exposes this header if the API lists it in
  // Access-Control-Expose-Headers.
  const nextSession = response.headers.get("x-session-id");
  if (nextSession) sessionStorage.setItem(SESSION_KEY, nextSession);

  return (await response.json()) as ChatResponse;
}

src/features/widget/ChatWidget.tsx

import { useOptimistic, useState } from "react";
import { askChatbot, type WidgetKeys } from "./chatApi";
import type { ChatTurn } from "../../lib/types";

export function ChatWidget({ keys, greeting }: { keys: WidgetKeys; greeting: string }) {
  const [history, setHistory] = useState<ChatTurn[]>([]);
  const [draft, setDraft] = useState("");
  const [failed, setFailed] = useState(false);
  const [turns, addTurn] = useOptimistic(history, (current, content: string): ChatTurn[] => [
    ...current,
    { role: "user", content },
  ]);

  async function ask() {
    const query = draft.trim();
    if (!query) return;

    setFailed(false);
    addTurn(query);
    setDraft("");
    try {
      const answer = await askChatbot(keys, query);
      setHistory(answer.history); // the server's history is the source of truth
    } catch {
      setDraft(query);
      setFailed(true);
    }
  }

  return (
    <section aria-label="Chat">
      <p>{greeting}</p>
      <ol aria-live="polite">
        {turns.map((turn, index) => (
          // Rendered as text, so model output can never inject markup.
          <li key={index} data-role={turn.role}>{turn.content}</li>
        ))}
      </ol>
      {failed && <p role="alert">That didn't send. Please try again in a minute.</p>}
      <form action={ask}>
        <label htmlFor="chat-query">Your question</label>
        <input
          id="chat-query"
          value={draft}
          onChange={(event) => setDraft(event.target.value)}
          autoComplete="off"
          required
        />
        <button>Send</button>
      </form>
    </section>
  );
}
